# A3 code fixes (pregame audit 2026-11-11)

## Bottom line
- P3 confirmed and fixed: `matchup_off_vs_def_rating_5g/20g` were never built (they named `def_defensiveRating_*_away`; the column is `off_defensiveRating_*_away`). The deployed feature lists contain no `matchup_*` column, so live predictions and bets cannot change.
- Modelling question left open: the matchup is built as `home offence - away defence`, which is the wrong sign for a defensive rating (a worse defence, higher rating, LOWERS the feature). Corr with home points on the 2026-11-01 set: 0.03 (as built) versus 0.39 / 0.44 for the sum form (5g / 20g). Not redesigned.
- New append-only table `bet_recommendations_log` (one row per game per run, `--only-unpriced` re-runs included, failures logged at ERROR and swallowed). `predictions_log_v2` and its CSV mirror are untouched.
- P5 cause found, and it is not a logic bug in the mirror: the production checkout sat on branch `live-odds-research` (no mirror code) from 10-25 23:52 to 10-29 23:16, so the settlements on the mornings of 10-27, 10-28, 10-29 were never copied into the CSV, and the mirror only ever looked at games settled in the current call. Fixed by reconciling every COMPLETED DB row on each `update_actual_scores`; on a copy of the production CSV it repairs exactly the 25 stale rows.
- P6: message now names the searched directory (absolute) and the working directory. Behaviour unchanged.
- Tests: see "Test results". Nothing failed before or after my changes.

Caveat for the lead: `team/train_baseline.py` lines 127-139 put every `matchup_*` column into the ML/spread candidate pool, so the NEXT retrain or training-set rebuild will see two more candidates and can pick them. That changes a future candidate, not the deployed set.
- Train/serve parity: `pytest -m db` result below (live frame and the training set both go through `add_derived_features`, so they stay equal).
- Modelling note (not changed): all three pairs are `home offence stat - away defence stat`. For `defensiveRating` (points allowed per 100 possessions) and `OPP_FG3A` (3-point attempts allowed) a higher value means a WORSE defence, which should raise the home offence's expectation. The difference cancels that. The conventional matchup is a sum relative to the league mean (`off_home + def_away - league_mean`). On the 2026-11-01 set, correlation with home points: difference form +0.028 (5g) / +0.036 (20g); sum form +0.388 / +0.444 (the sum form also carries the offence level on its own, so this is not a fair test of added value). The existing `matchup_3pa_vs_opp_3pa_5g` has the same form. I kept the minimal, consistent fix as instructed.
