# A2: are the walk-forward backtest results valid and accurate? (2026-11-11)

Everything here was recomputed with my own code (`common.py`, `mymetrics.py`, `check*.py`; stdout of every script in `logs/`, re-run all with
`bash reports/audit_pregame_2026-11/A2_backtest_validity/run_all.sh` from the worktree root). Nothing in the repo was edited. All intervals are day-bootstrap
(resample game dates, 1,000 draws, seed 42) unless stated.
Reference run: `E25_with_odds` (`predictions.csv`, `calibration_set_predictions.csv`, `features.json`, `fold_info.json`). These files are untracked, so I read them from
the production checkout (`reports/experiments/E25_with_odds/`, read-only). Features were checked on `data/processed/training_set_v1_reduced_2026-11-01.csv`.

## Bottom line

- **No leakage found.** Team-form features, roster BPM and the injury features reproduce exactly (max |diff| 2e-13; 125 features x 784 team-games; roster BPM for all 16,876 games; `inj_n_out` 99.2%) from rows dated strictly before each game. No same-day ordering problem, no fold contamination, the settle code is right, a shuffled-prediction placebo gives chance results.
- **What is wrong is comparability, not leakage.** E25_with_odds is the *pre-adoption* baseline (raw-margin spread model, legacy isotonic ML calibrator that emits exact 0/1 probabilities, 20%-of-rows calibration block, no refit). It is not the deployed form: ML log loss is 0.6318 / 0.6225 / 0.6194 depending on the clip (1e-12 / project 1e-6 / 1e-4), 0.0113 worse than `E13_combined_winners` (0.6112), which is the saved run closest to the deployed form. Spread and total are unaffected for the P2 conclusion.
- **P2 is confirmed, on both runs.** 5% rule priced at the close: spread 2,345 bets, hit 50.06%, ROI -4.42% [-8.3, -0.2]; total 3,530 bets, hit 49.97%, ROI -4.60% [-7.8, -1.5]; 93.8% / 86.2% of the bets fade the open-to-close move. At zero vig both are at 0.0% (+0.13 [-3.9, +4.5], -0.06 [-3.4, +3.2]). Open-priced total ROI +1.81% becomes -1.97% if the same bets are settled at the close (mean CLV +0.64 pts [+0.48, +0.79]).
- **Provenance problems that change what can be reproduced:** the 11-01 rebuild has no odds at all before 2019-20 (the archive CSV is missing; E25's 10-19 set had spreads/totals from 2017-18 at least), the model's "open" is one book (DraftKings first) while every evaluation close is a cross-book median, and the injury snapshot is a different report in different eras (night-before 8:30 PM in 2019-21, 11:30 AM 2021-25, 12:00 from 2025-26; live reads the 11:00 report).
- Tests: see check 10.

## Findings ranked by how much they could move a reported backtest number

1. **E25_with_odds is not the deployed estimator (high for ML, low for spread/total).**
   `experiments/lib.py` fits LightGBM on the raw margin/total with `odds_away_spread` and `odds_total` as the only line inputs (features.json), an isotonic ML calibrator and one global sigma; the deployed set uses `ResidualSpreadModel`, a margin-stack ML calibrator and a per-game sigma. E25 also predates the audit-fix harness (`split.json` absent): calibration block = last 20% of training rows, uncapped (fold sizes 1,576 / 1,805 / 2,039 / 2,304 / 2,568 / 2,831 / 3,095 reproduce `n - int(0.8 n)` exactly, `check6_folds.py`), no refit.
   Evidence the ML numbers depend on it: 55 of 8,916 games have `ml_prob` <= 0.001 or >= 0.999 (6 of them wrong); pooled ML log loss 0.6318 (clip 1e-12), 0.6225 (project clip 1e-6), 0.6194 (1e-4); 2023-24 alone is 0.6799 at clip 1e-12 against 0.5965 for the uncalibrated classifier; raw 0.6118 pooled beats the calibrated number. FINAL_REPORT's baseline ML log loss 0.6199 is therefore comparable to my 0.6194-0.6225 only through the clip choice.
   Run on `E13_combined_winners` instead (`logs/*_E13.log`): ML 0.6112, spread MAE 10.690 (open 10.676, close 10.510), total 14.700 (open 14.557, close 14.252); ML 5% bets 447, ROI +1.51%. Size of the difference: ML log loss -0.0113 pooled; spread/total MAE within 0.03 of E25.
2. **Open-priced ROI includes line movement the model's information set could not buy (medium-high, a known caveat, now sized).**
   Chosen at the open, settled at the close (-110): spread 644 bets ROI -4.84% [-12.5, +2.8] (open-settled -5.29%), CLV +0.17 pts [-0.02, +0.32]; total 1,928 bets ROI -1.97% [-6.1, +2.3] (open-settled +1.81% [-2.3, +5.8]), CLV +0.64 pts [+0.48, +0.79]. So about 3.8 ROI points of the open-priced total result is movement after the open. On E13: total +1.27% -> -2.70%, CLV +0.71.
3. **The 11-01 training set cannot reproduce E25 (provenance, medium).** Pre-2019-20 odds are zero in the rebuild (`check1b` log: odds coverage 0.000 for 2013-14..2018-19; DB `nba_odds_opening` has no book data before 2019; `data/nba_odds_archive.csv` is not in either checkout). E25's calibration blocks show odds present for 2017-18 and 2018-19 (spread 99.6-99.9%, moneylines 0%). For 2019-20..2025-26 the rebuild's targets and opening odds equal E25's on every game (target mismatches 0; opening spread/total/ML values equal on all games where both exist, one game's home ML missing in one of the two). A retrain on the rebuilt set trains on six NaN-odds seasons the old set did not have.
4. **Basis mismatch between the model's open and the evaluation close (medium).** The training `odds_*` come from one book (`core.odds_pick`: DraftKings first); evaluation lines `close_*`/`open_home_prob` are cross-book medians. The single-book spread equals the consensus open on only 59.9% of games (mean |diff| 0.30 pts, p95 1.25; total 56.1%, 0.39). SD of (close - open) is 2.18 with the single-book open vs 2.07 with the consensus open (spread), 3.40 vs 3.28 (total). The fade share and regressions in P1/P2 shift a little (spread fade 93.8% -> 91.6% with the consensus open; total 86.2% -> 85.9%). E25_decorrelation's ML edge slope depends on it: 0.394 [0.110, 0.695] against the single-book de-vigged open (README: 0.39 [0.09, 0.72], reproduced) but 0.194 [-0.089, 0.487] against the consensus open.
5. **Injury snapshot is a different report in different eras (medium, train/serve and drift).** The rule (latest report <= min(game-day noon ET, tip - 30 min), canonical grid) is applied correctly, but the chosen report's stamp is 8:30 PM the night before for most games of 2019-20 (969 of 1,147) and almost all of 2020-21 (1,204 of 1,211), 11:30 AM for 2021-22..2024-25 (about 1,320 games a season), 12:00 from late 2025-26 (897 games; hourly reports, `check4_injury_snapshot_choice.csv`). Live runs at about 11:19 ET and reads the 11:00 report (`data/raw/daily_inference.log`, every day 2026-11-06..11-11: "Newest injury report ... 11:00:00 (0.3 h before the cutoff)"). Team-games with `inj_missing`=1 ("not yet submitted"): 11.7-23.2% by season, 33-37% in 2026-27 (81 games). The walk-forward trains on staler injury information and tests on fresher.
6. **2026-27 closes are 30 minutes staler than the historical closes (low-medium).** `nba_odds` equals the last snapshot of the game in 99.4% (ML/total) to 99.7% (spread) of book-field cases, i.e. the line frozen at/after tip, not the last pre-game snapshot (equal only 51% ML, 80% spread, 69% total). The pre-game snapshot is a median 30 min before tip. `load_clean_odds` overwrites the 2026-27 close with the snapshot: close/open abs-error ratio 1.011 in 2026-27 against 0.977-0.996 in 2019-2025. Not contaminated: in-game rows sit 0.27-0.29 pts (spread) and 0.8-1.1 pts (total) from the last pre-game line with no steady growth after tip, and on 125 games MAE of `nba_odds` equals the pre-game snapshot (spread 11.212 vs 11.212, total 14.064 vs 14.064).
7. **Smaller items.** NBA Cup knockout games (gameId prefix 006) are absent from `team_game_full` (rest, load and EWMA of the finalists ignore them); play-in games (005, 36 test games) have `is_playoff`=0; BPM position comes from a static `player_info.POSITION`; `days_rest` is uncapped (up to 288 days at season starts) and `diff_days_rest` is selected in every fold; the train/val block boundary can split one night's games (a few games, no information flows); roster BPM for a team's first game of a season is last season's final roster (32 zeros only at 2013-14 openers).

## Check-by-check results

### 1. Feature leakage by recomputation: PASS
- `check1_recompute.py`: 392 games (28 per season x 14 seasons 2013-14..2026-27, seed 42) = 784 team-games, 125 features per team-game = 98,000 values, recomputed from `team_game_full` rows with `gameDate` strictly before the game, with explicit EWMA recursions (span 5 and 20; 22 offensive + 17 opponent-stat columns, their 39 trends, `days_rest`, `is_b2b`, `games_last_7d`, `season_game_number`, `win_pct_last10`, `win_streak`, `home_win_pct_20g`, `is_playoff`). Max |diff| 1.6e-13, no NaN mismatch, 100% within 1e-6.
- `check3_bpm_recompute.py`: my own BPM (per-player recursions, own position map, own 365-day trailing league mean). `roster_bpm` and `roster_bpm_ewma`: all 16,876 games, both sides, max |diff| 2.1e-13, except one game (0022600021, 2026-10-30, away) at 1.9e-3 / 3.5e-4, probably a box-score revision after the build. Poison test: overwriting every player box score dated on/after 2025-01-15 with random numbers changes no value for any game before that date or ON that date (max |diff| 0.0 over 29,480 earlier games), and changes later games (median |diff| 35), so no same-day or future row enters.
- `check1c`: 136 `diff_*` columns equal home minus away to 1e-9; `matchup_3pa_vs_opp_3pa_5g` = `off_threePointersAttempted_5g_home - def_OPP_FG3A_5g_away` to 1e-14. The 11-01 set has only that one matchup feature (the two `def_defensiveRating_*` pairs of P3 never exist: confirmed).
- `check1b_leakprobe.py` (416 numeric feature columns): correlation with the same game's margin / total / home win, largest outside the lines: `def_OPP_PTS_20g_home` with the total at 0.467 (no non-odds feature above 0.5; 17 above 0.4, all points/3PA-volume EWMAs vs the total). That is the NBA's scoring-era trend: on 2019+ rows where the market line exists, the form sum correlates 0.296 with the total against 0.415 for the opening total, and within season 0.259 vs 0.391. No feature equals any same-game box-score value of either team (327 values tried, best equality share 0.48 for 0/1 flags vs the home-win flag, by coincidence); highest |corr| with a same-game box-score value 0.75 (3PA EWMA vs that game's 3PA, a team tendency).
- Limit: verified on the 11-01 rebuild, not on the 10-19 set E25 trained on (lost). Same code, and every target and opening-odds value of the 8,916 E25 test games is identical in the rebuild.

### 2. Same-day ordering and game types: PASS
- `check2_segments.py`: `gameDate` is date-only (all 33,910 values 10 characters). No team has two games on one date (0 duplicates; max 1 per team-date), so a team's "previous game" is never same-day; doubleheaders do not exist in the data. Because each team's features read only its own earlier rows (verified exact in check 1) and the BPM league mean uses strictly earlier dates, other teams' same-day results never enter.
- Game types in the 8,916 test games: regular 8,289 (002), playoffs 590 (004, of which 83 in the 2020 bubble), play-in 37 (005). They are in training and test alike; only `is_playoff` (004 only) tells them apart, play-in counts as 0. The 2019-20 bubble (172 test games from 2020-07-30: 88 seeding, 1 play-in, 83 playoff) is not marked. NBA Cup group games are regular 002; knockout games (006) are not in the database at all.

Regular season only: ML log loss 0.6206, spread MAE 10.616 (open 10.560), total 14.794 (open 14.630).

### 3. Roster BPM timing: PASS
- Code (`core/player_features.py`, `core/bpm_builder.py`): a player-game's BPM uses his EWMA (span 40) of stats shifted by one game, cumulative minutes shifted by one game, and a league mean over [date - 365 d, date); the team's `roster_bpm` for game g is the previous game's value, `roster_bpm_ewma` the span-10 EWMA through the previous game. Reproduced exactly (check 1) and the poison test confirms it numerically.
- First game of a season: the previous season's last roster value (the roster is not updated for offseason moves); only the 32 first-ever 2013-14 team openers are exactly 0. Traded players: the previous-game roster is the team's actual previous lineup, so a player enters only after his first game for the team; the injury candidate set drops players whose latest appearance was for another team.
- `player_info.POSITION` is a static current label (small forward-looking element in the position coefficients of BPM; not tested).

### 10. Train/serve parity and tests
`tests/team/test_parity.py` rebuilds the training set from the current code (`GameFeatureBuilder.build_training_set`), runs the live path (`build_live_game_frame`, injury features as of noon through `build_injury_features(as_of=..., upcoming=...)`) for 2026-01-15, 2025-03-12, 2022-11-23, 2020-01-17 and asserts all >300 numeric columns equal to 1e-6, and that live builds every training column. It is marked `db`.
Results (`check10_pytest_full_output.txt`; nothing fixed): `pytest tests/team tests/core -q -m "not db"` gave 417 passed, 0 failed, 0 skipped (6 min). `pytest tests/team tests/core -q -rsxf` (adds the 8 `db` tests: the four parity dates, `test_live_frame_has_every_model_input`, the exact-opponent-columns test, `test_real_history_outputs_unchanged_by_vectorization`, `test_first_season_rates_use_no_later_data`) gave **425 passed, 0 failed, 0 skipped**, 6 min, 10 FutureWarnings from `prediction_logger.py`. So live and training features agree to 1e-6 on all numeric columns (more than 300) on 2026-01-15, 2025-03-12, 2022-11-23 and 2020-01-17.
Caveats: (i) the tests ran against the shared worktree while other workstreams were editing `team/` and `core/` (git status showed modified `game_features_v2.py`, `train_baseline.py`, `market_models.py`, `live_odds.py` and others that are not mine), so they certify the tree as it stood during the run; (ii) the parity test skips `odds_*` columns and feeds the injury path the noon cut (`as_of` = noon), so it cannot see the real live difference (the 11:19 ET run reads the 11:00 report, finding 5), and the training set it rebuilds has no pre-2019 odds (archive CSV missing); (iii) `test_first_season_rates_use_no_later_data` passes, consistent with my own check of the rate table in check 4. There is no test that the walk-forward harness's calibration/selection blocks exclude the test season on real data beyond `tests/team/test_experiment_lookahead.py` / `test_walk_forward.py` (both pass); check 6 covers that on E25's saved outputs.

## Not verified / limits
- Training was not rerun: the 10-19 training set E25 used is lost and the 11-01 rebuild differs (no pre-2019 odds), so I could verify fold construction, calibrators, sigma and features from saved outputs and code, not by re-fitting. The tuning-validation tail and selection-sees-only-`mt.iloc[:n_fl]` were checked by reading `experiments/lib.py` / `team/train_baseline.py`, not by an instrumented run.
- The deployed model files (`..._cand_20261019`) and the walk-forward form that matches them were not re-evaluated beyond E13's saved predictions; E13 uses the same legacy split scheme as E25 (no `split.json`), so its ML calibrator is the stack from E3 with the older calibration block.
- The history of opening-line posting times before 2026-10-19 is unknown (no snapshots); the claim that opening lines precede the noon report rests on the 2026-27 snapshots (median 17 h before noon, 5% of games after noon).
- The PDF report timestamps are taken as printed (ET); I did not check them against download times. Report names are matched by normalised text, the fuzzy path of `link_reports` is not independently reproduced (4 of 505 team-games differ).
- Totals with |close - open| > 15 and the 12 spread sign flips were not checked against an external source.
- `data/nba_odds_archive.csv`, the NBA Cup knockout games and the effect of the static `player_info.POSITION` could not be examined.
- The odds consensus is the project's (median of up to six books); I did not test other consensus definitions.
