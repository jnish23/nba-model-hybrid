## Exit codes and what `run_daily_inference.bat` does (text-only change; never executed)
| code | meaning | log line the owner sees (ERROR unless stated) | re-run scheduler | dashboard publish | final exit code of the task |
|---|---|---|---|---|---|
| 0 | normal run, a real off day (NBA lists no games), or a re-run with nothing to do | INFO `No games found today.` on an off day | runs | runs | 0 if both later steps are 0 |
| 1 | unexpected exception (bug or changed data format), also a duplicated SBR row (`MergeError`) | `INFERENCE RUN CRASHED: ...` with the full traceback | runs (unchanged) | runs (unchanged) | 1 |
| 3 | too early (B2 guard) | `RUN TOO EARLY: ...` | skipped | skipped | 3 |
| 4 | games on the NBA schedule, nothing predicted | `ODDS SOURCE FAILURE: ...` or `NBA SCHEDULE FAILURE: ...` or `ALL GAMES SKIPPED: ...`; `.bat` adds `NOTHING PREDICTED ...` | **skipped** | **runs** | 4 |
| 5 | predicted and logged, no bet recommended | `BETS SUPPRESSED (<code>): <detail> ...`; `.bat` adds `NO BETS RECOMMENDED ...` | runs | runs | 5 |

Decision (please confirm): **code 4 skips the re-run scheduler but still publishes.** The re-run scheduler only re-runs games already logged without a line; with nothing logged it would write a false "every game has its lines" status for the dashboard. The publish is idempotent and carries the results the morning sync just settled, and a dashboard without today's picks looks the same as after code 3. Code 3 keeps skipping both (unchanged). Codes 1, 4, 5 keep the first non-zero code as the task's result (the `.bat` already did that).

## Decisions for the owner to confirm
1. Code 4 skips the re-run scheduler and still publishes (see above). Alternative: skip both like code 3.
2. Suppression is per slate (all games of the day), not per game, and `injury_features_failed` also suppresses. A report 30 min behind the snapshot is NOT flagged (B2's tolerance, unchanged). In the half-hourly era (the live era) a download failure at 12:05 that leaves the 11:30 report is therefore not suppressed, although training reads the 12:00 report; tightening the tolerance to "more than 15 min" would flag it and still pass the old-era hourly files only if their header lag is dropped. Left as B2 set it.
3. `bet_suppressed_reason` stores the short code only (`injury_report_missing`, `injury_report_stale`, `injury_snapshot_mismatch`, `injury_features_failed`); the detail (age, file) is in the log line and in the existing `injury_cutoff_et` / `injury_report_file` columns.
4. `--no-wait-for-injury-cutoff` now also withholds the bets (a run at 11:15 ET reads the 11:00 report, a mismatch). Before it ran with a warning and recommended bets. There is no override flag; say if you want one.
5. An empty SBR current board is treated as an outage (exit 4) even if SBR legitimately had not posted yet. At 09:15 Pacific (12:15 ET) lines are up; a run before that would hit this.
6. `--only-unpriced` re-runs also write skip rows each time (append-only), and their exit codes 4/5 are ignored by `run_odds_rerun.bat` (it only returns the last step's code; unchanged, not my file).
7. 10 s / 30 s backoff and 3 tries for the scoreboard, SBR and the injury download (total at most about 40 s of sleeping per source, plus the download's own scan time).
