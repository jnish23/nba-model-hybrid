# B2: run-time guard for the injury-report cutoff

## Bottom line
- The daily run now waits (default up to 120 min, after the database sync) until the training snapshot's report can be read: latest game's cutoff + 5 min = **12:05 ET** for a normal slate. Earlier than that by more than the maximum: ERROR, exit code 3, nothing predicted or logged.
- After the report is fetched the run checks it against the snapshot; a report more than 30 min older than the nominal time logs `INJURY SNAPSHOT MISMATCH` (the post-DST 11:00 report at noon is 60 min behind and would have fired every day). The bet log now records the file really used.
- `run_daily_inference.bat` passes the Python exit code on (non-zero if any step failed; code 3 skips the two downstream steps). Not executed.
- Recommended fire time: **09:05 Pacific, as a local-time trigger, all year** (= 12:05 ET in both halves). If the trigger stays UTC-fixed it must be 17:05 UTC in winter and 16:05 UTC in summer.
- `pytest tests/team tests/core -q -m "not db"`: **446 passed, 8 deselected**. New file: 29 tests (`tests/team/test_run_time_guard.py`); A3's `test_bet_log_run.py` still passes (32 passed for the two files together: 29 new + 3 of A3's). `ast.parse` of `scripts/run_inference_v2.py` OK.

### 1. Guard (`injury_cutoff_guard`, called from `main()` between the DB sync and `InferenceEngine(...)`)
- Not applied when `--date` or `--only-unpriced` is given. Flags: `--no-wait-for-injury-cutoff` (proceed at once; WARNING if it is early), `--max-wait-minutes` (default 120).
- Ready time = `snapshot_nominal_cutoff(...) + REPORT_PUBLICATION_ALLOWANCE`. The nominal cutoff calls the training function `irf.SNAPSHOT_CUTOFFS['game_day_noon']` on a frame of (game date, tip) so the guard cannot drift from training: clock (noon) capped at tip - 30 min per game; the slate's cutoff is the latest of the games' cutoffs.
- Tip times: `gameTimeUTC` from the NBA scoreboard (the same call the run already makes, `get_nba_schedule`), converted UTC to ET with zoneinfo, so DST is handled by the zone database, not by an offset. `get_injury_features` itself takes tips from the PDF's printed game time (`irf.game_tip_times`) for the per-game cutoff; the guard only needs the slate's latest cutoff, and the two agree for any normal tip time.
- Slate cannot be fetched (exception, empty, no `gameTimeUTC`): clock rule (noon + allowance), logged at INFO. Unparsable tip: that game counts at the clock time (conservative).
- Early tips (decision): the guard waits for the report each game's own cutoff needs, i.e. max over games of min(noon, tip - 30). One evening game keeps the noon rule (the evening games need the noon report). Only a slate where EVERY game has tip - 30 < noon waits less: e.g. tips 11:00 and 11:30 ET give cutoffs 10:30 / 11:00, ready 11:05, not 12:05. The guard never waits past the latest cutoff + allowance. Tested.
  - The same slate cutoff now also sets the `as_of` passed to `fetch_report` and the `injury_cutoff` stored in the bet log (it was `min(now, game_date + noon)`). Identical for any slate with a game tipping at 12:30 ET or later; differs only on an all-early slate, where the old value asked for a report newer than any game needs.
  - Open issue, not changed: a mixed slate (a 12:00 ET game plus evening games) waits until 12:05, after the early game has tipped; the run does not exclude started games (it did not before either: the old 12:15 fire was also after a 12:00 tip).
- Wait loop: sleeps in steps of at most 30 s (`WAIT_STEP_SECONDS`), one INFO line at the start, one at the end.

**Allowance evidence** (`report_lag_evidence.py`, output in `report_lag_evidence.out`; read-only listing of names and modified times in `C:/Users/jorda/nba-model-hybrid/data/raw/injury_reports/2026`): 456 files stamped since 2026-10-20; 371 were written within 2 min of the stamped slot (min / median / max 0.13 / 0.20 / 1.63 min). The 12:00 slot specifically: 11 days since 2026-11-01, written 0.13-0.42 min after noon. The other 85 were written later by a bulk restore (10-25..29) or rewritten by the daily run (the 11:00 slot, ~11:17 ET). `core/scrape_injury_reports.py` says files are "typically stamped ~:30 past the slot hour" for the hourly era; in the 2025-26/2026-27 half-hourly era the parsed header time equals the slot time (`injury_reports_parsed.csv`: lag 0 min for 1,604 of 2,046 report files since 2025-10, 30 min for 423, 45 for 18; all 4,796 files of 2022-10..2025-09 carry the +30 min header). So the nominal-time report is downloadable within seconds; **5 min** = three times the slowest prompt download. Caveat: 11 days of evidence for the noon slot; the first 5 days of the data are restored, not live.

### 2. Verification of the report used (`get_injury_features`)
- `check_report_freshness` (existing, 6 h threshold) stays. New: if the newest report at/before the cutoff was published more than `STALE_SNAPSHOT_TOLERANCE` = 30 min before the slate's nominal cutoff, log ERROR `INJURY SNAPSHOT MISMATCH: the report used is <file> (published HH:MM ET), N min older than the game_day_noon time 12:00 ET; the training snapshot reads the report published at 12:00 ET ...`.
- Tolerance is 30 min, not one grid step (60 min) as the brief suggested: an 11:00 report at noon is exactly 60 min behind, and "more than 60" would not have fired on the failure that motivated this. 30 min still admits the old-era files (header 30 min after the slot, so noon training read the 11:30 report). Checked on the cases in the tests.
- Bet log: `injury_cutoff_et` = the cutoff (min(now, slate cutoff)), `injury_report_file` = the download path if it is the file used, otherwise the bare name of the file the features really came from (before: `None` when the download failed). No column added. **Proposed column** (not added): `injury_snapshot_gap_min REAL` = nominal cutoff minus the used report's publication time, so a stale snapshot can be selected in SQL; a NULL/0 means as trained.
- Not checked: per-game verification. The check uses the slate's nominal cutoff and the newest report for that date; a per-game early-tip game that read an older report is not flagged.

### 3. `run_daily_inference.bat` (CRLF kept; never executed)
Comments now say the script waits for the injury cutoff and that the task is meant to fire at 09:05 Pacific = 12:05 ET (local-time trigger). Behaviour:

| inference exit | log lines | schedule_odds_rerun | export --publish | final exit code |
|---|---|---|---|---|
| 0 | start line, python output | runs | runs | 0 if both later steps are 0, else the first non-zero of them |
| 3 (too early) | `INFERENCE EXIT CODE 3`, `TOO EARLY: nothing predicted ...` | skipped | skipped | 3 |
| other non-zero (crash) | `INFERENCE EXIT CODE n` | runs (picks up unpriced games) | runs (safe: republishes what is in the DB) | n |

A final `DONE exit code n` line is written (not on the exit-3 path, which exits first). Why skip on 3: with no predictions for today `schedule_odds_rerun.py` would record "every game has its lines" in the status file and the publish would republish unchanged data. Old behaviour: always ran all three, exit code of the last step only.
Open: whether the task has an execution time limit shorter than the maximum wait (120 min) was not checked (Task Scheduler is off limits).

## Recommended task fire time (local Pacific)
Noon ET is 09:00 Pacific in both halves of the year (the zones change clocks the same night), so the noon report is readable at **09:05 PT**, winter and summer. Fire at 09:05 PT: the sync (2-7 min in the log) runs first, so the run reaches the guard at about 09:07-09:12 PT, after the report is readable, and the wait is zero. A later fire (e.g. 09:15 PT = 12:15 ET, the pre-November time) also works but reads current lines further from the opening lines the model sees (see the lead's P1); an earlier fire is covered by the guard (up to 120 min) rather than silently wrong. The trigger must be a local-time trigger; it drifted because it was fixed to a UTC offset (16:15 UTC = 09:15 PDT = 08:15 PST). A UTC-fixed trigger would need 17:05 UTC in winter and 16:05 UTC in summer.
